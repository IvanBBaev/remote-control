# 07 — QA / test strategy

Status: 2026-10-12. Role #7 (senior QA / test-strategy engineer). Input: `00-brief.md`,
`01-roles.md`, the owner's test conventions in `kiko` and `agenthropic` (read-only), and
the sources in §9. Interfaces this report needs from other roles are marked **[needs #n]**.

## 1. Summary

1. One runner for the whole monorepo: **vitest** with `test.projects` (node for relay/agent/
   protocol/crypto, jsdom for web). `node --test` loses on fake timers, coverage thresholds
   and multi-environment projects; the owner already runs vitest in agenthropic.
2. Build the **fakes before any feature**: `packages/fake-claude-code` (a Node executable that
   resolves hooks from a temp `HOME/.claude/settings.json` and fires them exactly as the docs
   say), `packages/test-harness` (relay in-process on PGlite + port 0, agent in-process,
   headless phone in Node reusing `packages/protocol` + `packages/crypto`, fake clock, fake
   push sink, log capture).
3. Database in tests: **PGlite** on every PR (all three OSes, no Docker); a real Postgres
   `services:` job on `main` + nightly. Testcontainers rejected (needs Docker; no Docker on
   hosted macOS runners).
4. Every MVP journey (pair, allow, deny, AskUserQuestion, expiry, agent offline, phone
   offline, sessions/diff, new instruction, new session, allow-list refusal, revoke) is an
   in-process integration test with zero network beyond localhost; target < 60 s total.
5. Crypto: Node WebCrypto is the every-PR "browser"; a Playwright spec on Chromium + WebKit
   decrypts Node-generated vectors on `main`/nightly. jsdom+polyfill rejected.
6. Playwright: Chromium with iPhone emulation + CDP virtual authenticator for passkey
   journeys (9 specs), WebKit smoke (2 specs); push simulated by dispatching `PushEvent`
   inside the service worker. Runs on `main`, nightly and PRs labelled `e2e`.
7. Definition of green on a PR: single required `ci` job (typecheck, lint, format, build,
   unit + contract + integration with coverage thresholds, **privacy gate**) plus the
   `agent-os` matrix (macOS, Windows). Playwright and real Postgres are `main`/nightly.
8. Privacy gate = canary strings planted in every payload; after each journey the captured
   relay/agent logs **and a dump of every relay table** must not contain any canary.
9. Real iPhone push, Face ID, real Claude Code, Railway: a written manual checklist per
   release, including re-recording hook fixtures and diffing their key sets.

## 2. Verified facts

### 2.1 Claude Code hooks (what the fake must reproduce)

- Hooks live in `~/.claude/settings.json` (user), `.claude/settings.json` (project,
  committable) and `.claude/settings.local.json` (project, gitignored); `--settings
  '{"disableAllHooks": true}'` turns them off for a run.
  <https://code.claude.com/docs/en/hooks-guide>, <https://code.claude.com/docs/en/hooks>
- When an event fires, Claude Code runs **all matching hooks in parallel**; input is JSON on
  stdin; output via exit code and stdout JSON. Exit 0 + valid JSON = decision; exit 2 =
  block (where the event allows it); any other exit = non-blocking error. Invalid JSON is a
  non-blocking error. <https://code.claude.com/docs/en/hooks-guide>
- Handler types: `command`, `http` (POST the same JSON to a URL; 2xx JSON body uses the same
  output schema; non-2xx or connection failure = non-blocking error), `mcp_tool`, `prompt`,
  `agent`. `PermissionRequest` does not support `agent` hooks; `SessionStart` does not
  support `http`. <https://code.claude.com/docs/en/hooks>
- Timeouts: per-hook `timeout` in seconds; default 600 s for command/http/mcp_tool (30 s for
  `UserPromptSubmit` and some others); `"async": true` on a command hook runs it in the
  background and it cannot block. <https://code.claude.com/docs/en/hooks>
- `PermissionRequest` input: `tool_name`, `tool_input`, optional `permission_suggestions`,
  `mcp_server`; **no `tool_use_id`**; decision via
  `hookSpecificOutput.decision.behavior` = `allow` | `deny`; a matcher of `.*` returning
  allow auto-approves everything. <https://code.claude.com/docs/en/hooks>
- `PreToolUse` output: `hookSpecificOutput.permissionDecision` = `allow` | `deny` | `ask` |
  `defer`, plus `updatedInput`; this is the documented route for answering
  `AskUserQuestion` (`updatedInput.answers`). <https://code.claude.com/docs/en/hooks>
- Other inputs: `Notification` (`message`, `title`, `notification_type` such as
  `permission_prompt`, `idle_prompt`, `elicitation_dialog`, `agent_needs_input`),
  `PostToolUse` (`tool_response`, `tool_use_id`, `duration_ms`), `Stop` (`stop_hook_active`,
  `last_assistant_message`), `SessionStart` (`source`: `startup`|`resume`|`clear`|`compact`|
  `fork`), `UserPromptSubmit` (`prompt`), `SessionEnd` (`reason`). Common: `session_id`,
  `prompt_id`, `transcript_path`, `cwd`, `scratchpad_dir`, `permission_mode`, `effort`,
  `hook_event_name`, `agent_id`/`agent_type`. <https://code.claude.com/docs/en/hooks>
- `CLAUDE_PROJECT_DIR` is set in the hook's environment. Hooks from a project settings file
  do not run until the workspace-trust dialog is accepted. `claude --debug` writes
  `~/.claude/debug/<session-id>.txt`; `--debug-file <path>` picks the location.
  <https://code.claude.com/docs/en/hooks>

### 2.2 Test runner

- vitest `test.projects` lets one root config run per-package projects with their own
  `environment` (node / jsdom); coverage is configured once at the root.
  <https://vitest.dev/guide/projects>
- `coverage.thresholds` supports `lines`, `functions`, `branches`, `statements`, `perFile`,

### 2.3 Postgres in tests

- PGlite is Postgres compiled to WASM, ~3 MB gzipped, `new PGlite()` is in-memory,
  single-user / single-connection. <https://pglite.dev/docs/>,
  <https://github.com/electric-sql/pglite>
- drizzle has a first-class PGlite driver: `drizzle-orm/pglite`, `drizzle()` in-memory or
  `drizzle({ client })`. <https://orm.drizzle.team/docs/connect-pglite>
- `@electric-sql/pglite-socket` exposes the wire protocol (no SSL; multiplexed connections
  "not all use cases guaranteed"). <https://pglite.dev/docs/pglite-socket>
- Testcontainers for Node requires a container runtime: Docker, Podman, Colima or Rancher
  Desktop. <https://node.testcontainers.org/supported-container-runtimes/>
- GitHub Actions `services: postgres` works on Linux runners only; readiness via
  `pg_isready` health options; reachable on `localhost:5432` for job steps.
  <https://docs.github.com/en/actions/use-cases-and-examples/using-containerized-services/creating-postgresql-service-containers>

### 2.5 Crypto

## 4. Findings

- **H-roles "fake Claude Code and fake phone from day one" — confirmed, sharpened.** The fake
  is not a stub of our own adapter; it is a reimplementation of the documented hook runner
  (settings merge, matcher regex, parallel execution, stdin/stdout/exit-code contract, timeouts,
  `http` handlers) that spawns the **real hook command the agent installs**. Only then does an
  integration test prove that the agent's registration, the hook script and the agent's
  localhost listener work together.
- **H4 "PermissionRequest blocking, holds for minutes" — testable; verified mechanism.** The
  default 600 s timeout and exit-code semantics are documented (§2.1). The fake enforces the
  timeout the same way, so "phone answers after 9 minutes" and "expired at 10" are ordinary
  tests with a fake clock. **[needs #4]** to confirm the chosen timeout value and whether the
  agent returns `deny` or no decision on expiry.
- **H4 "exact hook set ... must be verified" — changed.** `AskUserQuestion` is answered on
  `PreToolUse` with `updatedInput.answers`, not on `PermissionRequest`. The fake and the
  journeys cover both events.
- **H3 "`node --test` or vitest" — changed to vitest.** Reasons: one config with per-package
  environments (jsdom for the PWA), built-in coverage thresholds, fake timers with async
  advancement, the owner's agenthropic precedent. kiko's `node --test` style (inject deps,
  `app.inject`) is kept as the test *style*.
- **H4 "E2E encryption phone ↔ agent" — confirmed, with a testability requirement.**
  `packages/crypto` must be isomorphic (WebCrypto only, no Node `crypto` import) with
  injectable randomness and clock; otherwise the headless phone cannot run in Node and the
  browser vector test cannot load the same bundle. **[needs #2]**
- **H4 "fresh user-verifying assertion per Allow" — testable in Chromium only.** The CDP
  virtual authenticator covers registration, UV assertion, "assertion bound to this request"
  and "stale assertion rejected". WebKit/iOS passkeys are manual (§5.14).
- **H4 "Web Push" — partially testable.** Push delivery itself cannot run in CI. Three
  layers replace it: unit tests of the SW's pure `handlePush`/`notificationclick` functions, a
  fake push service asserting VAPID/TTL/Urgency headers and a non-plaintext body, and a
  Playwright test dispatching `PushEvent` inside the SW. Real device push is manual.
- **H "relay sees only metadata" — turned into a machine gate.** Canary strings in every
  payload, dumped relay tables and captured logs must not contain them (§5.12).
- **H4 "Agent SDK vs interactive CLI" — testing consequence.** Whichever wins, the agent must
  put it behind a `SessionLauncher` port; the harness supplies a fake implementation. If the
  CLI/pty route wins, the fake Claude Code needs an interactive mode (reads stdin prompts,
  emits a Stop hook), which is an extra M item (WI-22). **[needs #4]**
- **H "agent on macOS, Windows, Linux" — confirmed, scoped.** Settings merge, hook spawning
  and service-file generation are deterministic and run on the three runner images; actual
  service loading is a smoke step, not a gate, until A2 is proven.
- **H "`node --test` vs vitest in CI on three OS" — note.** The `agent-os` matrix runs only
  the agent project plus the fake Claude Code conformance table; the full suite runs once on
  ubuntu to keep the matrix under ~3 min.

## 5. Recommendations

### 5.1 Runner: vitest with projects

Root `vitest.config.ts` with `test.projects` per package; `environment: 'node'` everywhere
except `apps/web` (`jsdom`). Coverage v8 at the root with glob thresholds (§5.13).
Alternatives: `node --test` + c8 (kiko) — no fake timers, no jsdom project, thresholds via
c8 only; mixed runners — two configs for one developer. Both lost.

### 5.2 Database: PGlite every PR, real Postgres on main

Relay takes a `Db` built by `drizzle-orm/pglite` in tests and `drizzle-orm/node-postgres` in
production (same drizzle schema; migrations applied on the PGlite client before each suite).
One `new PGlite()` per test file; vitest runs files in parallel workers, so the single-
connection limit never bites. `pg-real` job (ubuntu, `services: postgres`, `main` + nightly)
runs migrations and the integration suite against real Postgres to catch SQL that PGlite
accepts but production rejects (and vice versa).
Alternatives: Testcontainers — needs Docker, impossible on macOS runners and heavy locally;
`services:` only — Linux-only and slow for every PR; SQLite — a different dialect. All lost.

### 5.3 `packages/fake-claude-code` (build first)

Private workspace package, library + CLI (`fake-claude`). Behaviour, each item a test named
after the doc sentence it implements:

- `loadHooks({ home, cwd })` merges `~/.claude/settings.json`, `.claude/settings.json`,
  `.claude/settings.local.json`; honours `disableAllHooks`.
- `fire(event, input, { timeoutMs?, clock })` selects matchers (regex on `tool_name` for tool
  events), runs all handlers in parallel, sets `CLAUDE_PROJECT_DIR`, writes stdin JSON,
  applies per-hook `timeout` (defaults 600 s / 30 s), parses stdout, maps exit codes
  (0+JSON, 2, other), handles `async: true`, supports `type: 'http'` (POST, 2xx JSON body,
  non-2xx = non-blocking error). Returns `{ decision, updatedInput, errors[] }`.
- `scenario(file)` plays a scripted session: `SessionStart` → `UserPromptSubmit` →
  `PreToolUse`/`PermissionRequest` → `PostToolUse` → `Stop` → `SessionEnd`, appending a fake
  transcript JSONL as it goes so `transcript_path` points at a real file.
- CLI: `fake-claude fire PermissionRequest --fixture bash-rm-rf --home /tmp/h --timeout 5`
  for manual use and for the OS matrix (`exit 0/1/2` mirrors the decision).

Alternatives: stubbing the agent's hook listener directly (misses settings merge, quoting,
Windows shell, timeouts) — lost; running real `claude -p` in CI (needs credentials, costs
money, nondeterministic) — lost, kept as manual (§5.14).

### 5.4 Recorded hook payloads as anonymised fixtures

- Capture on the owner's machine with a recorder hook registered temporarily in a throwaway
  project's `.claude/settings.local.json` for every event; it appends stdin verbatim to
  `~/Development/_temp/hook-recordings/<event>-<ts>.json` and exits 0 with no output
  (no decision, so Claude Code behaves normally). Drive a short scripted session (one Bash,
  one Edit, one `AskUserQuestion`, one idle).
- `pnpm fixtures:anonymise <dir>` rewrites: `cwd`, `transcript_path`, `scratchpad_dir` →
  `/home/synthetic/project/...`; `session_id`, `prompt_id`, `agent_id`, `tool_use_id` → fixed
  synthetic ids; every string inside `tool_input`, `tool_response`, `prompt`, `message`,
  `last_assistant_message`, `permission_suggestions` → same-shape placeholder; keeps the key
  set, `tool_name`, `hook_event_name`, `permission_mode`, `notification_type`, `source`,
  `reason`, `stop_hook_active`. Adds `_meta: { claude_code_version, captured_at }`.
- Tests: (a) every fixture validates against the agent's hook input schemas; (b) no fixture
  string matches `/Users/|/home/(?!synthetic)|C:\\Users|ivan|baev|@gmail/i`; (c) the key set of
  each fixture equals a committed snapshot (so a doc change is a visible diff).
- Refresh is manual, per release (§5.14), because CI never runs real Claude Code.

### 5.5 Fake transcript JSONL

Reuse the agenthropic pattern (`jsonLine({...})`, synthetic ids, `/home/synthetic/project`):
a `transcript-builder.ts` with `user()`, `assistant({ toolUse })`, `toolResult()` producing
the fields the agent's parser reads. The scenario runner (§5.3) uses it; the "live sessions /
steps / diff" journey asserts the agent's parsed steps against the builder's known input.

### 5.6 `packages/test-harness`

- `startRelay({ db = pglite(), clock, push = fakePushSink, logs = capture })` → Fastify
  `listen({ port: 0 })` (needed: `app.inject` cannot do WebSockets) returning `{ url, wsUrl,
  db, push, logs, close }`.
- `startAgent({ relayUrl, home, allowList, clock, launcher = fakeLauncher })` in-process; the
  hook listener binds a random localhost port; `agent.installHooks()` writes the temp
  settings.
- `createPhone({ relayUrl, crypto, authenticator = fakeAuthenticator })` — headless client:
  register/login (fake WebAuthn producing valid structures for `@simplewebauthn/server` via a
  software authenticator), pair, subscribe to push (fake subscription), receive requests,
  `allow()/deny()/answer()`, go offline/online. **[needs #3]** envelope and WS protocol,
  **[needs #2]** pairing steps.
- `FakeClock` shared by relay, agent and phone (ports from WI-2) so expiry is deterministic;
  vitest fake timers are used only in pure unit tests.
- `captureLogs()` swaps the pino destination for an in-memory sink.

### 5.7 Protocol / contract tests (`packages/protocol`)

- Golden fixtures: one JSON file per message type and version in `fixtures/v1/`; test
  `decode(encode(x)) == x` and `decode(fixture) == expected`, plus `encode` is byte-stable.
- Version negotiation: table of (phone v, agent v, relay v) → accepted/rejected/downgraded;
  unknown fields ignored, unknown message type rejected with a typed error.
- Envelope idempotency: a `Dedup` with injected clock; same `(senderDeviceId, seq)` twice →
  second ignored; window expiry with fake time.
- Outbox replay: in-memory outbox port; disconnect mid-stream → reconnect → ordered redelivery,
  no duplicates, ack cursor advances. Property test (A5): any interleaving of
  `send/disconnect/reconnect/ack` yields the exact set and order of messages.
- "Decision bound to the exact request": property over random `(requestId, nonce, payloadHash)`
  — a decision for any other tuple, or a replayed decision, is rejected by the agent-side
  verifier. **[needs #2]** the exact bytes that are signed.
- Expiry: request created at t0, phone decides at t0+timeout+1 → agent rejects and reports
  `expired`; at t0+timeout-1 → accepted (fake clock, boundary tests both sides).

### 5.8 Crypto tests (`packages/crypto`)

- Deterministic vectors generated by a script with injected RNG, committed as JSON (hex), and
  a test that regeneration equals the committed file. Vectors: pairing key agreement, HKDF
  derivation, AEAD encrypt/decrypt with AAD = envelope header, signature over the decision
  tuple.
- Negative tests: tampered ciphertext/AAD/nonce → fails; replayed nonce → rejected; MITM at
  pairing (attacker substitutes a public key; the short authentication code / QR secret check
  must fail) **[needs #2]** for the exact pairing design; revoked device key → every message
  rejected after revocation, including queued ones.
- Cross-environment: every PR runs the suite on Node WebCrypto (same W3C API as browsers;
  Ed25519/X25519 stable since 22.13). On `main`/nightly a Playwright spec loads the built
  `packages/crypto` bundle in Chromium **and WebKit**, decrypts/verifies the Node vectors, and
  encrypts a message that the Node test then decrypts.
  Alternatives: jsdom + `@peculiar/webcrypto` (a polyfill, proves nothing about browsers;
  Node already has WebCrypto) — lost; Playwright on every PR (slow for one line of crypto
  change) — lost.
- Lint rule: `packages/crypto` may not import `node:crypto`.

### 5.9 Integration journeys (every PR, in-process)

One file per journey under `apps/*/test/journeys/`, all using §5.6:

| Id | Journey | Key assertion |
|----|---------|---------------|
| J1 | register + passkey login + pair phone | relay stores only device ids/public keys; phone and agent share a key |
| J2 | `PermissionRequest` → push sent → allow with UV | fake Claude gets `allow`; push sink has 1 message with non-plaintext body |
| J3 | deny | fake Claude gets `deny` and the agent's decision log has the device id |

| J5 | expiry | fake Claude times out at `timeout`; late decision rejected as `expired` |
| J6 | agent loses relay mid-request, phone decides, agent reconnects | decision delivered once (outbox), within the hook timeout |
| J7 | phone offline when request arrives | push sent; on reconnect the request is listed once; decision works |

### 5.10 Playwright for the PWA

- Config: `webServer: [harness relay (port fixed via env), vite preview]`; project `mobile-
  chromium` = `devices['iPhone 13']` + `permissions: ['notifications']`; project
  `mobile-webkit` = `devices['iPhone 13']` on WebKit, smoke only.
- Helpers: `withVirtualAuthenticator(page)` (A1) and `dispatchPush(context, payload)` that
  waits for SW activation then runs `worker.evaluate(() => self.dispatchEvent(new
  PushEvent('push', { data })))`.

### 5.11 Agent on three OSes

`agent-os` matrix (`ubuntu-latest`, `macos-latest`, `windows-latest`), ~3 min:

- Hook registration into a temp `HOME` (`USERPROFILE` on Windows): pre-seed
  `settings.json` with unrelated hooks and settings → `agent hooks install` → JSON contains
  ours and theirs unchanged; second run is a no-op (byte-identical); `agent hooks uninstall`
  restores the original byte-for-byte; corrupted JSON → refuses with a clear error.
- `fake-claude fire` on each OS spawns the installed hook command and the agent answers (path
  quoting, PowerShell vs sh).
- `agent service install --dry-run --home <tmp>` emits the launchd plist / systemd user unit /
  Windows service definition; snapshot per OS. **[needs #6]** for the CLI surface.
- Real service load (`continue-on-error: true`, A2) with install → status → uninstall.

### 5.12 Privacy gate

- Static: eslint `no-console` in `apps/relay` and `apps/agent` (entry files excepted); the
  logger accepts only an allowlisted set of top-level keys (`kind`, `requestId`, `deviceId`,
  `userId`, `sessionRef`, `durationMs`, `err.code`), enforced by a type and a runtime guard.
- Dynamic: every fixture and journey payload embeds canaries such as
  `CANARY-TOOLINPUT-<random>`, `CANARY-PROMPT-...`, `CANARY-PATH-...`, `CANARY-ANSWER-...`.
  After each journey: captured relay logs, captured agent logs, every relay table dumped as
  text, and the fake push sink's bodies must contain **zero** canaries. A meta-test plants a
  deliberate leak and asserts the gate fails.
- Forbidden log keys (fail if present at any depth): `tool_input`, `tool_response`, `prompt`,
  `message`, `last_assistant_message`, `transcript_path`, `cwd`, `answers`, `plaintext`.

### 5.13 Coverage and gates

Thresholds (global per project, not per file): `packages/protocol` and `packages/crypto`
100 % on all four metrics; `apps/agent`, `apps/relay`, `packages/test-harness`,
`packages/fake-claude-code` 90 lines / 85 branches; `apps/web` 80 / 70. Coverage-honesty test
(no `v8 ignore` / `istanbul ignore` pragmas) copied from agenthropic. Definition of green:

| When | Required | Also runs |

| every PR | `ci` (ubuntu: audit → typecheck → lint → format → build web → unit+contract+integration on PGlite with thresholds → privacy gate), `agent-os` (macos, windows) | — |
| push to `main` | the above | `e2e` (Playwright), `pg-real`, browser crypto vectors |
| nightly | — | `e2e`, `pg-real` on latest runner images; failure notifies the owner |

Branch protection requires the contexts `ci`, `agent-os (macos-latest)`,
`agent-os (windows-latest)`; `enforce_admins` off, as in agenthropic.

### 5.14 Manual test plan per release (`docs/release-checklist.md`)

1. `claude --version` recorded; run the recorder session (§5.4), anonymise, diff key sets
   against committed fixtures; update fixtures and the fake if anything changed.
2. Agent: `npx` install on macOS, Windows, Linux; `agent hooks install`; service survives
   reboot; uninstall leaves no files.
3. Real Claude Code: Bash permission → phone push arrives with screen locked (iPhone and
   Android); tap opens the request; Face ID / fingerprint on Allow; Claude continues;
   `AskUserQuestion` answered from phone; deny; let one request expire.
4. Connectivity: phone on mobile data, computer at home; agent reconnects after Wi-Fi
   drop; WS idle > 10 min through Railway stays up.
5. Sessions: list, steps, diff, last turn match the terminal; new instruction; new session in
   an allow-listed repo; refused outside it.
6. Security: revoke phone → it stops receiving; pair second phone; lost-phone flow.
7. Privacy: grep Railway logs and a `pg_dump` for the canary planted in a test prompt.
8. Railway: deploy from `main`, migrations applied, health endpoint, cost page checked.

## 6. Risks

| Risk | Likelihood | Impact | Mitigation |
|------|-----------|--------|------------|
| Claude Code changes hook payloads/semantics; fake and fixtures drift silently | high | high | fixtures carry `claude_code_version`; key-set snapshot tests; release step 1 re-records; fake tests named after doc sentences so a doc diff maps to tests |
| The fake Claude Code diverges from the real runner (quoting, env, timeout) | medium | high | OS matrix spawns the real installed hook command; manual step 3 is the oracle |
| PGlite accepts SQL that Postgres rejects (or vice versa) | medium | medium | `pg-real` job on `main`/nightly with the same suite |
| Virtual authenticator option names differ (A1) or CDP changes | medium | low | helper isolated in one file; WI-12 verifies first |
| WebKit lacks Ed25519/X25519 features chosen by #2 | low | high | browser vector spec on WebKit from the first crypto commit |
| Real-service load on runners fails for runner reasons (A2) | high | low | `continue-on-error`; dry-run snapshots are the gate |
| Playwright flakiness on `main` erodes trust | medium | medium | no retries by default; trace on first retry; quarantine tag with an issue link; budget 5 min |
| Privacy gate gives false confidence (leak via a path not captured) | medium | high | gate covers logs, DB dump and push bodies; manual step 7 on production |
| Recorded fixtures leak owner data into a public repo | low | high | anonymiser test + owner review of the first batch (Q4) |
| Test harness becomes a second product and stalls features | medium | medium | harness only grows when a journey needs it; sizes in §7 are caps |
