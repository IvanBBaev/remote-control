## 1. Summary

The automated base is broad and honest about I1 and I3 on the PWA path:
- 2 672 tests pass, with 97–98 % coverage;
- 12 journeys pass, with a canary privacy gate and a planted-leak meta-test;
- Noise KK/XXpsk0 vectors run in Node, Chromium and WebKit;
- the agent itself checks a tampered relay-vouched decision (J2, W15).

The gaps sit where the next release lands:
- The native app has about 70 % of its source excluded from coverage. That includes the Secure Enclave signer, the key store and the relay transport. The mobile "100 %" threshold therefore measures only `src/core`.
- The device-key Allow path has no reproducible automated end-to-end test.
- The fake Claude Code fixtures are generated by the fake itself.
- Under CPU contention the suite turns flaky, with 36 time-budget failures.

**Verdicts:**
- **M1 release:** ready-with-fixes. The automated gates are fine; real-CLI and owner evidence are still pending (M0-23b, M1-14b, M1-15b).
- **Native-app TestFlight (M4-08):** not ready from a QA standpoint until F1 and F2 are closed.

## 3. Assumptions

- A1. The V23 failures come from contention, not regressions. The 2026-10-28 gate was green, and a different test failed on each rerun. They still show how wide the budgets are. CI runners (2–4 vCPU), v3 parallel lanes running `pnpm check` side by side (PARALLEL.md), and Windows runners are all slower than an idle M-series laptop.
- A2. The authoritative invariant text is ROADMAP §1 (`ROADMAP.md:155-167`). I map tests against that text.
- A3. The vitest JSON statuses are accurate. Some skips are counted per test and some per suite. The 8 in V2 match the env gates one to one.
- A4. The XCUITest runs recorded in `native-app.md` happened as described. I did not re-run them.

## 4. Findings

### F1 — High — Mobile coverage "100 %" measures 30 % of the app, and the policy cannot see it
**Evidence:**
- V4: the exclude glob drops `app`, `ui`, `state` and `adapters`;
- V5: the coverage policy ignores `exclude`;
- V6: about 70 % of the TS lines and all the Swift are untested in the repo.

The excluded `adapters/` holds `device-signer.ts`, `secure-key-store.ts` and `relay-transport.ts`. These turn a Face ID result into an ES256 decision and keep the X25519 keys. `state/` (418 lines) holds the store reducers the inbox uses to show and decide on a request. Neither has UI-only logic that would justify "verified by screenshots".

**Why it matters:**
- The 100 % mobile floor is a false signal to TestFlight reviewers.
- A refactor of the signer (for example the V3 `android` lane's Android branch of `device-signer.ts`) can break DER formatting, decision hashing or key reuse with the gate green.
- Any future glob added to `exclude` would equally bypass D18 floors without review.

**Touches:** I1 (decision bound to the request and signed by the paired device), D18 (floors), ADR 0017, M4-04 AC.

### F2 — High — The native device-key Allow path has no reproducible automated end-to-end test
**Evidence:**
- V7: the XCUITests live only in a git-ignored `ios/`; the committed `.swift` files are documentation;
- V8: no Secure Enclave–produced fixture and no harness journey with a device-key phone;
- V9: phone-core flows never run on the noble backend.

The M4-04 AC "app Allow works end to end in the simulator" is proven by screenshots and a local, unreproducible UI target. The agent side is unit-tested only against a software P-256 key that we encode to DER ourselves. So a mismatch between iOS `SecKeyCreateSignature` output and `verifyEs256` would only show on a device, and so would a mismatch in the hashed canonical decision bytes.

**Why it matters:** TestFlight (M4-08) is the first time real users rely on this path. There is no regression net between now and then, and none after it. The V3 `android` lane will add a second signer branch with the same exposure.

**Touches:** I1, ADR 0017, ADR 0010, M4-04, M4-08, R7.

### F3 — High — Fake Claude Code conformance is self-referential; fixtures were never recorded from the real CLI
**Evidence:** V16 and V17. `key-sets.json` is a snapshot of the fake's own output. The 25 conformance cases check the fake against our reading of the docs (04 §2), not against the binary. No `compare` step exists.

**Why it matters:**
- Every journey (J2–J10) and the hook budget logic trust the fake's payload shapes and its timeout and exit semantics.
- A Claude Code release that renames a key or changes the hook timeout default goes unnoticed by CI. R15 covers hooks as the only source, but nothing *detects* the drift. That is the risk M0-23b exists to close, and it is blocked on the owner.
- The missing piece is not the recording (M0-23b, V2-AG-01 already own it). It is a check that fails once a recording exists and differs from the fake.

**Touches:** I2 (hook timeout semantics), R1/R3, R15, D18, M0-23b.

### F4 — Medium — Time budgets are tuned to an idle laptop; the suite turns flaky under contention
**Evidence:**
- V23: 36 budget failures at load ≈ 93, and a different test fails on each rerun;
- V24: `settle()` counts macrotask turns instead of waiting for a condition;
- V25: the `crypto-noble` properties run at the 5 s default;
- V26: 42 `vi.waitFor` calls use the 1 s default;
- V27: a write that is not awaited survives test teardown, as an unhandled `ENOENT`.

**Why it matters:**
- The v3 plan (PARALLEL.md §1) runs several lanes' `pnpm check` at once on one machine.
- Windows and macOS CI runners are slower than the dev box.
- Flaky gates train executors to re-run until green, and that hides real races. V27 points to a real race in the agent: a file write still running after `run()` resolved and the abort finished.

**Touches:** D18 (journeys under 60 s), ROADMAP §0 gate discipline, R12 (shutdown cleanliness).

### F5 — Medium — The privacy gate is substring-only and skips two relay egress channels
**Evidence:** V11, V12 and V13.
- `includes(canary)` misses a canary that leaks base64-, hex-, URI- or JSON-escaped. The relay handles base64 frames everywhere, so a debug log of a frame would carry the canary encoded.
- Relay HTTP response bodies and WS frames sent to the phone are never scanned. The relay could echo a field it should not keep, and the gate would still pass because it reads only logs and the DB.
- J11 never calls `assertNoLeaks`.

APNs and Sentry are covered by unit tests (`apns-sender.test.ts:81,97`, `push-core.test.ts:225`, `error-reporting.test.ts:37-70`), but not by the journey gate.

**Touches:** I3, D18 privacy gate, W-S12 (v2, relay never sees `request_id`). W-S12 is a narrower static test; this finding is about the dynamic gate.

### F6 — Medium — Three different definitions of I1–I4 are in use
**Evidence:**
- `ROADMAP.md:155-167`: I1 = no action without a phone decision, I2 = no hanging hook, I3 = metadata only, I4 = npx, keep-alive, no auto-update.
- `docs/analysis/review/00-state.md:24-27`: I1 = no plaintext, I2 = no stored payload, I3 = no authority, I4 = agent never grants.
- `packages/test-harness/src/canaries.ts:4` and `privacy-gate.ts:2`: "I1 plaintext / I2 payload".

**Why it matters:**
- Test names, ADR "Enforcement point" fields (V3-S01) and this review series all cite invariants by number. With three mappings, a test labelled "I2" may enforce I3.
- Nothing maps each invariant to its enforcing tests, so a gap like F2 for I1 on native stays invisible.

**Touches:** I1–I4, V3-S01 (ADR "Enforcement point" field).

### F7 — Medium — Journeys run against a second, hand-wired relay composition root
**Evidence:** V14. `startRelay` duplicates the wiring of `apps/relay/src/container.ts` on PGlite, without Sentry, the APNs flag, admin or the production bus wiring. Production `container.ts` is at 33 % function coverage.

**Why it matters:**
- A wiring bug in `container.ts` passes all 12 journeys and P1–P9, because e2e also uses the harness `startRelay`. Examples: a port bound to the wrong adapter, a missing rate limiter, or a push sender wired before the redactor.
- Lanes append wiring blocks to `container.ts` (PARALLEL.md §3), and this is the riskiest file for that.
- `main.test.ts` boots the real server once and only checks `/health` and migrations.

**Touches:** I3 (redaction wiring), D2 (one container per app), R7.

### F8 — Medium — The WebKit smoke never makes a decision
**Evidence:** V22. iOS Safari is the primary PWA target, and on WebKit no Allow, Deny or answer is ever sent. That covers the passkey ceremony, the decision envelope and the service-worker notification action. The reason is real: WebKit has no virtual authenticator in Playwright. But a Deny or an answer needs no passkey (D7: Deny skips UV), and that path is still not run.

**Touches:** I1 (decision binding on WebKit), D18 (WebKit smoke), M1-12.

### F9 — Medium — Windows correctness rests on three journeys and skipped adapters
**Evidence:** V19. The `file-key-store` permission tests are `posixOnly`, and no Windows replacement checks the ACL or `icacls` protection of the agent key. J8–J11 never run on Windows. The matrix runs J1, J2 and J5 only.

**Why it matters:** I4 promises that one `npx` command works. The agent key is the I1 trust anchor on the machine, and on Windows its file protection is unverified.

**Touches:** I1, I4, R12, D18 agent-os matrix.

### F10 — Low — e2e harness hygiene
**Evidence:** V20 and V21.
- Locally, a running `vite preview` on 4173 answers `/health` through the SPA fallback. With `reuseExistingServer` on, Playwright then tests the wrong server.
- `retries: 1` in CI turns a flake into a pass, and nothing reports it.
- The service-worker loops have no bound, so a hang shows up only as the 30 s test timeout with no message.
- The fixed 700 ms wait slows every decision spec.

**Touches:** D18 Playwright gate.

### F11 — Low — Soak smoke can never fail; low branch coverage on two security adapters
**Evidence:**
- V18: the soak smoke is continue-on-error.
- V1: `apps/relay/src/adapters/simple-webauthn.ts` has 62.5 % branch coverage (lines 74-106, the verification error branches), and `pg-db.ts` 56 % lines (only exercised by pg-real).

The duplicate-decision and leak counters in the soak are the only multi-minute I2 and I3 signal per OS, and a regression there goes green.

**Touches:** I2, I3, M1-15, R14.

Not findings (checked and fine):
- the browser crypto vectors (V10);
- the env gating of the 8 skips (V2);
- I4 no-auto-update and zero-runtime-deps tests (`package.test.ts:69-75`, `cli/update.test.ts`);
- the planted-leak meta-test.

## 5. Recommendations

1. **Police coverage excludes and pull logic out of the excluded mobile dirs (F1).**
   - Add an allow-list of `coverage.exclude` globs to `coverage-policy.test.ts`. Each glob must carry a justification string, and `apps/mobile/src/adapters/**` must not be on the list.
   - Then unit-test the pure parts of `device-signer.ts`, `secure-key-store.ts` and `relay-transport.ts` with the native module mocked: payload hashing, DER passthrough, key-reuse rules and error mapping. Do the same for the `state/` reducers.
   - Rejected: lowering the mobile threshold to an honest 70 %. That keeps the blind spot.
   - Rejected: React Native Testing Library for `ui/`. It costs a lot, and the screens carry little logic after V3-S03d.
2. **Lock the native signature contract with a golden fixture and a harness journey (F2).**
   - Capture one real Secure Enclave signature (SPKI, canonical decision, DER signature) from the simulator run the owner already does, and commit it as `apps/agent/src/testing/fixtures/se-es256.json`. Have `device-signature-check.test.ts` verify it.
   - Add `j2-device-key.test.ts` with a headless phone that signs with a P-256 key through the mobile `authorize` path on the noble backend.
   - Rejected: CI XCUITests on macOS runners. That needs an `ios/` prebuild in CI, simulator boot time and Apple signing; it belongs with V3-C11 `mobile-release.yml`.
3. **Make fixture drift detectable (F3).** Add `pnpm fixtures:compare <recording-dir>`. It anonymises a real recording and diffs its key-sets against `key-sets.json`, exiting non-zero on a new or missing key. Record in `claude-code-hooks.md` which real version the fixtures match.
   - Rejected: running the real `claude` in CI (cost, auth, D18 "fake in CI").
4. **Make budgets condition-based and scaled (F4).**
   - Replace `settle()` with `vi.waitFor(cond, { timeout })`.
   - Give `crypto-noble` a 20 s `testTimeout`.
   - Add a shared `RC_TEST_TIME_SCALE` multiplier, read by `eventually`, the journey timeouts and the `waitFor` defaults (`test.vitest.config` `expect.poll`/`waitFor` defaults).
   - Fix the write that is not awaited, found in V27.
   - Rejected: `retry: 2` in vitest. It hides races like V27.
5. **Harden the privacy gate (F5).** Have `findLeaks` also search the base64, base64url, hex and JSON-escaped forms of each canary. Add `relay-http` and `relay-ws-out` taps in the harness relay as leak sources. Make J11 call `assertNoLeaks`. Extend the planted-leak meta-test with one encoded leak.
6. **One invariant map (F6).**
   - Fix `00-state.md` and the harness comments to the ROADMAP §1 text.
   - Add `docs/testing/invariants.md`, which maps I1–I4 and J1–J12 to test files.
   - Add a test that fails when a mapped file disappears.
   - Rejected: renumbering ROADMAP §1. Decisions and ADRs already cite it.
7. **Boot journeys through the production container (F7).**
   - Have `startRelay` call `createContainer` with PGlite and fakes injected through its existing options.
   - Delete the hand wiring, keeping only the seams.
   - Rejected: a separate container smoke test. It would leave two roots to keep in sync.
8. **WebKit Deny and answer (F8).** Extend `webkit.spec.ts` with a Deny and a question answer, which need no UV. Keep the passkey Allow in the device checklist.
9. **Windows (F9).** Add a Windows `file-key-store` test that asserts the ACL via `icacls`, and add J8 and J12 to the matrix journey list.
10. **e2e hygiene (F10).**
    - Move the default ports to 47173 and 47174.
    - Make `/health` assert a relay-specific JSON body before reuse.
    - Bound the service-worker loops.
    - Report retried-then-passed tests as a job annotation. Set `failOnFlakyTests` on the nightly run.
11. **Soak and adapters (F11).** Gate the soak smoke on `duplicates == 0 && leaks == 0`, keeping RSS growth report-only. Add a test for each `simple-webauthn.ts` error branch.
