## 2. Cross-cutting themes
**T1 — The native app cannot sign in on a release build** (04, 09; critical for M4-08).
- *What is wrong:* only the `__DEV__` DeveloperRelay authenticates. There is no passkey
  sign-in, enrolment, revoke or account deletion. The last two are also App Store
  requirements (guideline 5.1.1(v)).
- *Fix:* RV-UX-06/07/08 (these absorb RV-MOB-05) become explicit M4-08 dependencies.
  ADR 0017:68 already names a native passkey on the Q2 domain.

**T2 — Railway Config as Code is ending** (06 F1; high).
- *What is wrong:* `railway.json` is ignored by services created after 2026-08-28, and
  existing files stop being read on 2026-12-01. Railway's docs confirm both.
- *Impact:* the production service does not exist yet, so the first deploy would silently
  lose the health check, the pre-deploy migrate, the drain/overlap settings and the
  restart policy.
- *Fix:* RV-OPS-01 ports the settings to `.railway/railway.ts` (which D16 already named),
  with an ADR.

**T3 — The deploy overlap splits the relay state** (02 F1; high).
- *What is wrong:* the default `RC_HUB=local` plus about 45 s of overlap means two
  processes each hold half of the presence and pending state.
- *Fix:* RV-RLY-01 makes production run the pg hub (ADR 0016), and adds a test that runs
  two processes.

**T4 — Browser trust surface** (01 F1/F2, 05 F1).
- *What is wrong:* the relay serves the PWA's JavaScript and sends no CSP or security
  headers, and SECURITY.md claims more than the PWA delivers.
- *Fix:* RV-SEC-02 adds the headers and CSP. RV-SEC-01 documents the PWA as a
  convenience client, with the native app as the high-assurance one (Q-RV-01).

**T5 — Evidence gap: real CLI and real devices** (03, 04, 07, 00-state §5.1).
- *What is wrong:* the fake-CLI fixtures are generated by the repo itself, there is no
  reproducible device-key end-to-end test, and the Swift targets have no CI.
- *Fix:* RV-QA-05 (drift against a real recording), RV-QA-03/04 (a golden Secure Enclave
  fixture and a noble journey) and RV-MOB-09 (a macOS CI job).
- These tighten what M0-23b and M4-08 will prove. They do not replace those runs.

**T6 — Requests that nobody can answer** (03 F1/F2, 04, 05 F4).
- *What is wrong:*
  - the agent holds for about 30 minutes when no phone can answer;
  - only one request can be pending per session, so subagent fan-out loses prompts;
  - a push subscription can silently go stale;
  - the native app does not reconnect on foreground.
- *Fix:* RV-AGT-01/02/03, RV-WEB-03/04, RV-MOB-01/02.

**T7 — Load-sensitive and incomplete gates** (07 F1/F4/F5).
- *What is wrong:*
  - the tests wait with sleeps (`settle()`) and fixed timeouts, so they fail under load
    (the review itself saw 36 failures at a load average of about 90);
  - mobile coverage excludes most of the app;
  - the privacy gate only searches for literal strings.
- *Fix:* RV-QA-06/07/08, RV-QA-01/02.

**T8 — v3 parallel lanes are mis-scoped** (08 F1/F2).
- *What is wrong:*
  - Four hotspots are missing from PARALLEL §3: `session-hub.ts`, the phone-core
    `apply()` switch, and `runCommand` and `HELP_TEXT` in `cli/main.ts`.
  - The version-gate lane does not own the files where the handshake actually happens.
    These are `relay-router.ts:474`, the agent's `relay-client.ts:159` and phone-core.
- *Fix:* RV-ARC-01 first, then the modularity items in phase C.

**T9 — Docs drift and onboarding friction** (01 F3, 06 F3, 09 F2/F3).
- *What is wrong:*
  - SECURITY.md, the runbook's admin commands and the invariant numbering are out of
    date. The numbering in 00-state is already fixed; the code comments and an invariant
    map remain.
  - The phone tells the user to run `npx remotectl`, which contradicts ADR 0002.
  - `login` needs a hand-edited relay URL.
- *Why it matters:* the second-user run (M1-14b) would fail on these first.
- *Fix:* RV-UX-01…05, RV-OPS-03/08/12, RV-QA-09.

## 6. What this review did not settle
- **Test results:**
  - The reviewers' test runs overlapped with each other on one machine (load average
    about 80–90) and produced timeout failures: 36 in one full run, plus crypto property
    tests and web.
  - These are evidence for T7, not regressions. The gate result that counts is the
    `pnpm check` on an idle machine, recorded in the WORKLOG entry for this review.
- **Unverified assumptions:** they are listed in each report under "Assumptions". The
  biggest are:
  - real Claude Code hook behaviour (A-1, subagent fan-out);
  - iOS user-activation timing;
  - `railway run` reaching a private Postgres.
- **Out of scope:**
  - the v2 and v3 roadmaps, which are cited and not re-planned;
  - Android native, which is gated by Q-V3-7.
