# Holistic project assessment (2026-11-01)

Status: evidence gathered 2026-11-01 at `main` = `d3d7b4a` (12 commits ahead of
`origin/main`); live items re-checked 2026-11-06. Read-only assessment, one session. It
cites the as-built review (`SYNTHESIS.md`, `ROADMAP-review.md`, `00-state.md`) and the
v2/v3 corpora instead of repeating them. Nothing here changes a decision; the owner
actions it recommends are the ones the roadmaps already gate on.

## Verdict
The project is release-grade in code and gates and has **no production evidence yet**.
Everything left before the M0 and M1 exit gates is an owner action in the real world:
buy the domain, deploy the relay, run the real `claude` CLI, run on real devices, publish
to npm, name the second user. The main risk is not the code. It is the gap between
"88 % done" in the roadmap and zero deployments, next to a planning corpus (v2, v3, review)
that grows faster than the evidence. The 24 h soak has failed twice because the machine
slept, not because of the product.

## Findings

### 1. Product and kill criterion
- The kill criterion (ROADMAP §1) has not fired. Public sources as of 2026-11-01 show
  Claude Code Remote Control still bound to claude.ai OAuth (no API keys, Bedrock or
  Vertex) and give no sign of an "Always allow" decision from the phone or of non-Claude
  agents. This matches the v3 synthesis verdict of 2026-10-28. Sources are secondary
  (see Sources); verify against the official docs on the owner day.
- The market is moving to classifier-approved actions and cloud sessions. The window for
  "signed, verified, private approvals" is real and narrowing; evidence, not features,
  decides whether it is worth more than 1.x minors (v3 Q-V3-1 default).

### 2. Architecture and code
- Ports and adapters are enforced, not declared: lint forbids `Date.now`, `Math.random`
  and `crypto.getRandomValues` outside the Clock/Random ports and `node:crypto` outside
  `packages/crypto`; coverage thresholds are 100 % for log/protocol/crypto/mobile core and
  85–95 % elsewhere; production code has no `any` casts.
- Hotspots are the three largest files above plus `pg-notify-hub.ts`, `relay-router.ts`
  and `hooks-installer.ts`. They are covered by RV-ARC-01/02 and review theme T8; not
  urgent, but every v3 lane touches `main.ts` and `session-hub.ts`.
- Duplication: `apps/web/src/{realtime,pairing,auth}` still hold about 1 100 non-test
  lines next to `packages/phone-core`. Candidate for a dedupe item after the owner day.
- `apps/mobile/ios` (1.4 GB, untracked) is a local build artefact; fine, but note it in
  the mobile run book so a fresh clone knows to regenerate it.

### 3. Tests and gate
- `pnpm check` is green with a soak running in parallel. Tests are load-sensitive (review
  theme T7, `settle()`), which matters on a machine that runs several sessions.
- The e2e jobs (`browser-crypto`, `playwright`, `webkit`) are skipped on pull requests and
  are not required checks on `main`. Required checks are `ci`, `agent-os`, `image`;
  `enforce_admins` is off. The nightly e2e and pg-real runs are green.

### 4. Documentation and governance
- Four planning surfaces: ROADMAP (v1), v2, v3 and the as-built review. v2 is all `todo`
  or gated; v3 has four `done`; the review has one `done` of 101. Combined they hold
  well over 100 unstarted items on top of an unproven v1.
- Project `CLAUDE.md` is stale: it still says "No code yet" and its read order omits
  the v2, v3 and review corpora.
- The release-progress block says "Updated 2026-10-17" while §4 rows were edited on
  2026-10-30 and 10-31; rerun the progress skill after the next WP.
- ADR numbers 0018–0022 are missing on disk but reserved in `v3/PARALLEL.md` §4 for v3
  lanes, so the gap is intentional.
- Drift already catalogued: the phone says `npx remotectl` against ADR 0002 (theme T9);
  admin command docs (RV-OPS-03); runbook drift (RV-OPS-08).

### 5. Operations and release

- Railway Config as Code ends 2026-12-01; covered by RV-OPS-01 (`6aa2e28`).
- `auditConfig.ignoreGhsas`: the node-forge entry is due for removal after 2026-11-03;
  the zod entry has no expiry. RV-OPS-06 (expiry test) is still `todo`.
- Dependabot: PRs #1–#6 were all closed unmerged (each superseded by the next grouped

  been merged, so the lockfile drifts one grouped PR at a time.
- 12 commits on `main` have not been pushed since 2026-10-29 (push only on request).

### 6. Security
- Invariants I1–I4 are enforced structurally (E2E payloads, metadata-only relay, agent
  never grants). Open items from the review: RV-SEC-02 (CSP and security headers on the

- Theme T1: a native release build cannot sign in, because only `__DEV__` wires the
  DeveloperRelay. M4-08 (TestFlight) is "not ready" by all four review roles.

## Live findings: the 24 h soak (M1-15b)
- Run 1 (2026-10-29) failed on RSS growth; cause fixed in `256e77e` (challenge-ledger
  prune) and the verdict hardened (median growth after a 1 h warm-up, `awake` check).
- Run 2 (started 2026-10-31 09:55 under `caffeinate -dims`) failed the `awake` check:
  84 rounds in 26.51 h. `pmset -g log` shows the Mac on battery with the lid closed from
  about 10:40 on 2026-10-31 until a lid wake at 00:42 on 2026-11-01. `caffeinate` cannot
  prevent lid-close sleep on battery; the run book already says "lid open, on power".
  The same morning also shows "Dark Wake Thermal Emergency" sleeps on AC, so machine
  load is a second factor.
- Run 3 needs: AC power, lid open (or clamshell with an external display), fewer
  parallel sessions. Two cheap hardening items for `soak-cli`: refuse to start on
  battery (`pmset -g batt`) and fail fast when rounds fall behind wall time instead of
  running 24 h to a certain FAIL.
